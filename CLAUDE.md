# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Research tooling for SPX options: computing dealer **GEX (gamma exposure)** and **gamma walls** from the daily option chain, plus a study of the intraday **0DTE** (SPXW same-day expiry) order flow. Data comes from Databento (OPRA options, CME ES futures) and yfinance (the SPX close). Code, comments, identifiers and commit messages are all in **Spanish**. Keep writing in Spanish.

## Commands

Windows, venv in `venv/`. Run everything from the repo root, because cache paths like `data/raw` are relative.

```powershell
venv\Scripts\activate
pip install -r requirements.txt          # requirements.txt is UTF-16 encoded

$env:DATABENTO_API_KEY = "db-..."        # required, see below
python -m pytest                         # all tests (pytest.ini sets pythonpath=. and testpaths=tests)
python -m pytest tests/test_forward.py::nombre_del_test   # single test
python scripts/ver_gex.py                # scripts take dates as positional args, e.g.
python scripts/comparar_versiones_gex.py 2026-09-24 2026-09-29
```

- `config.py` raises `ValueError` at import time if `DATABENTO_API_KEY` is unset. Several test modules import it transitively (through `gex`), so **tests need the variable set**. The `odte` download modules create the client lazily and no longer need it at import. Any dummy value works. The tests make no network calls (yfinance is monkeypatched).
- There is no linter/formatter config and no build step.

## Data and cost rules (important)

Databento downloads cost real money. Every download path follows the same pattern:
1. A **cache-first** parquet in `data/raw/` (gitignored). If the file exists, no API call is made.
2. Otherwise **`metadata.get_cost` first**, then an interactive `s/n` confirmation on stdin, and only then the download.

For multi-day ranges, `datos.asegurar_cadenas(fechas, raices)` sums the cost of every missing (date, root, schema) and asks for **one** confirmation for the total. After that, `descargar_cadena` reads from the cache without prompting. Range scripts (`validar_gex`, `b2_flujo`) use this single-confirmation pattern. Do not reintroduce one prompt per day.
The generic form is `datos.asegurar_descargas(pedidos, descripcion, solo_costo)`, where `pedidos` is a list of (path, `get_range` params, `procesar`). It is the one place for cache check, total cost, one confirmation, download and save. Use it for any new download:
- `odte.trades.asegurar_tcbbo({fecha: símbolos}, desde, hasta, solo_costo)` is the tcbbo range download for the whole project (`b2_flujo`, `signo_walls`, `medir_niveles`, 0DTE).
- `odte.descargas.asegurar_odte({fecha: (kmin, kmax)})` handles a 0DTE range with at most **two** confirmations: catalog + ES, then tcbbo. The tcbbo cost needs the catalog's symbols first.

Do not bypass this, and do not run a script on uncached dates without the user knowing it will prompt for and spend credit. Cached dates cost $0. In `src/datos.py`, cache/cost messages go to **stderr** so that script stdout stays clean for before/after diffs. The `antes.txt`/`despues*.txt`/`gex_*.txt` files at the root are such captures, written by PowerShell redirection and therefore UTF-16.

## Architecture

**Core pipeline (`src/`)**, daily chain → GEX:
- `datos.py`: the only layer that talks to the outside world. `descargar_cadena(fecha, raices)` fetches the `ohlcv-1d` + `statistics` schemas per root (`SPX` monthly AM, `SPXW` daily/weekly PM) and returns `(precios, oi)` deduplicated to one row per symbol. `precio_spx(fecha)` is the **single** source of the SPX close (`odte.precio.cierre_spx` is an alias). The Databento client is created lazily.
- `simbolos.py`: the **single** OSI symbol parser (`'SPXW  261016C07800000'`). It was consolidated from 6 copies, so always use it rather than re-parsing. It raises on an unexpected format.
- `black_scholes.py`: price/IV/delta/gamma with an optional continuous dividend `q`. With `q=0` the results are exactly the pre-dividend behaviour. Edge rule: `T<=0` → intrinsic value / expiry delta, and IV and gamma are `nan`.
- `precio_justo.py`: `tabla_cierre(fecha)` gives the closing bid/ask mid per option from the already-downloaded `statistics` (stat_type 8 = bid, 7 = ask, 9 = OI). It exists because the last trade was stale for ~74% of options.
- `forward.py`: the implied forward per expiry from put-call parity on ATM-forward strikes (median, with reported dispersion). This gives the implied `q`. Expiries with too few strikes inherit `q` from the nearest measured one (`origen="heredado"`).
- `gex.py`: `construir_cadena(fecha, S, metodo)` with two methods:
  - `"mid_forward"` (**default since Oct 2026**, "versión C"): closing mid, all options with OI, `q` measured per expiry.
  - `"ultimo_trade"` (the original, kept for comparison): last trade price, only traded options, `q=0`.

  The default changed for **valuation** reasons: the unused OI is ~25% of the book, missing IVs created phantom walls (the 7000 wall on 24-sep), and the last trade was stale. It did **not** change for predictive reasons, since next-day range prediction came out even between the two methods. The docstring records this, so keep it accurate. Changes to the default method must be deliberate. The project compares methods side by side instead of silently replacing one.

  Two more parameters, both off by default (default output is bit-identical to before they existed):
  - `raices=("SPX",)` (default, monthly AM only) or `("SPX", "SPXW")`, which adds the daily/weekly PM short-dated gamma. The forward is measured **per root** (`forward.q_por_raiz`). `forward_por_vencimiento` raises if given more than one root, because SPX AM and SPXW PM share the third-Friday expiry and strikes.
  - `plazo="dias"` (default, calendar days/365) or `"horas"`, which is NY close of `fecha` → 9:30 (SPX) / 16:00 (SPXW) of expiry, DST-aware. `simbolos.plazo_anios` is the **single** place T is computed. Use `"horas"` with SPXW.

  The chain carries `raiz` and `dte` columns. It **excludes the same-day expiry (0DTE)** by design: `T > 0` at the close of `fecha` drops what expires that day, since it has no IV or gamma left. The `fecha−1` chain already holds those series (dte=1), with the older OI. On 2026-11-09 the user decided **not** to add the 0DTE, because it contributes very little. At the 11-04 close the next day's expiry was 0.7% of the OI and 2% of the gross gamma. The 0DTE OI published on 11-05 was 371k contracts, 5–17k per 25-pt zone against loads of 65k–545k. Don't propose adding it again without new evidence. `gex_por_plazo(cadena)` breaks the total down by root × DTE bucket (`1-3d`, `4-7d`, `8-35d`, `>35d`). This SPXW work lives on branch `spxw-raices`. Tag `antes-spxw` marks main before it.

  `gex_contrib = gamma · OI · signo · 100 · S² · 0.01`. Here `signo` comes from `signo_gamma_supuesto`, which derives it from `HIPOTESIS_NULA_PUBLICO` (the public sells calls and buys puts) through the `odte.dealer` sign table. It is an **assumed** sign, not a measured one, so don't hard-code `+1/−1`. Two views of the profile:
  - `gamma_walls` buckets the strikes into `banda`-point zones and returns the top `+` zones above and the top `−` zones below the spot. That split bakes in the convention that "above = resistance, below = support".
  - `niveles_gamma` ranks zones by `|gex_neto|` with no such convention. It reports position, calls/puts, `pct_abs` and `signo_supuesto` as columns. With an optional `medido` series (net public contracts per strike under the strict rule) it adds `signo_medido`, where `"sin evidencia"` means below `MIN_ABS_NIVEL`=200 and `"no medido"` means the zone had no flow.
- `trade_sign.py`: classifies trades on specific strikes (e.g. walls) by the price-vs-mid rule.

**Fase B, assumed vs measured dealer sign (`src/`)**:
- `inventario.py` (B1): OI per date and option, `delta_oi` against the previous date in the series (the `nueva` flag marks an option seen for the first time), and `por_zona`. It is sign-neutral and only reads the cache. **Time rule (confirmed, with tests):** the OI in day *d*'s file is the OI at the close of *d−1*, so the ΔOI of *d* is explained by the flow of the **previous** market day (`fecha_flujo`, which raises if there is no previous day).
- `signo_medido.py` (B3): `veredicto(neto_medido, delta_oi, accion_supuesta)` returns `confirma` / `CONTRADICE` / `demasiado chico` / `no atribuible` / `sin ΔOI`. It only gives an opinion when both minimums hold: `MIN_ABS`=200 contracts and `MIN_REL`=20% of the ΔOI. `pct_delta_indet` and `pct_oi_supuesto` measure how much of a wall's sign is assumption.
- Phase B result: 98–99.9% of the walls' sign is **assumed**. The assumed sign and the measured flow are always shown side by side and are **never merged** into one GEX number. The strict classification has three states (buy at ask / sell at bid / indeterminate), and the indeterminate part is never redistributed.
- `signo_walls.py` + `scripts/signo_walls.py` (branch `spxw-raices`): the same B2/B3 measurement on SPX+SPXW calls **and** puts for the transition zones 7700–7775 and the balanced 8000 wall. It reads `data/procesado` (no chain cost); only the tcbbo costs (~$6.26 for 512 series × 17 flow days, now cached). Pairs whose ΔOI spans a data gap (file 10-21) get no verdict. Result (`data/b2/signo_walls.csv`): all 10 zone-type cells are **"demasiado chico"**. 85–96% of the volume is indeterminate, ~30% prints outside the bid/ask (packages), and trades of ≥100 contracts are 97% indeterminate. Per day: 144 of 170 cells too small, 13 confirm and 10 contradict, with no consistent direction. **The strict rule cannot sign these walls.** Their sign stays assumed, now with measured evidence of why.
- `paquetes.py` (`signo_walls.py --paquetes`, $0 from cache): it rebuilds packages from prints of different series in the same ms. The placebo is 0 combos when calls are shifted 3–61 s, so the packages are real. Only C+P combos at the same strike and expiry are classified, by the INFERRED side of each leg:
  - **synthetic**: gamma-neutral whatever the direction.
  - **straddle**: ±2γ, which the null hypothesis scores as 0.

  Result: these combos are only ~3–4% of the walls' volume. 8000 is 89% synthetic, 7750/7775 ~70%, 7700/7725 ~46%. The net straddle is ≤1.5k contracts against a ΔOI of 100k+. This does **not** change the verdict. Most package legs fall in series that were not downloaded (other strikes and expiries), so their partners are invisible.

**Wall evolution (`src/walls.py`, `scripts/walls_tiempo.py`)**: tracks how loaded each wall is and why its GEX changes. Between two chain snapshots, ΔGEX splits **exactly** into three parts, tested in `tests/test_walls.py`:
- **posicionamiento**: ΔOI × today's k
- **mercado**: yesterday's OI × Δk, which covers price, time and IV
- **vencidas**: expired options leaving the book

Here k = gex_contrib/OI. The ΔOI excludes expirations, because an expiry is not a closed position. The script processes SPX+SPXW with `plazo="horas"` and caches each processed chain in `data/procesado/`. That folder is gitignored and saves ~2 min per day of compute. Use `--sin` for days missing at Databento (2026-10-20 has no data); the flow label then shows the extra sessions. Finding over 24-sep..21-oct 2026: the total GEX mostly tracks spot. The "mercado" part had the same sign as the SPX move on 17 of 18 days. Individual walls persist by **rotation**: weekly expiries are replaced by new OI at the same strikes.

**Measured vs assumed contract and the panel:**
- `walls.py` declares `MEDIDAS`, `MODELO`, `SUPUESTAS` and `CLAVES`. `clase(col)` returns `"medido"`, `"modelo"` or `"supuesto"`; it and `es_supuesta(col)` raise on an unclassified column. A test requires every output column to be classified.
- **MODELO** = Black-Scholes gamma · OI with **no sign**: `gex_bruto` (calls + puts, added, not netted) and `desbalance_pct` = |calls − puts| / gross. Under the null hypothesis it equals |gex| / gex_bruto exactly, but it is defined sign-free. A low value means the net GEX is a subtraction of two large numbers, so it is fragile to the sign assumption. A value near 100 does not make the sign measured.
- `app/panel.py` is a Streamlit + Plotly panel, run with `streamlit run app/panel.py`. It only reads `data/procesado/`: it never imports `datos`/`config`, so it needs no API key and cannot spend credit.
- All panel styling comes from the contract:
  - Assumed values get a diverging scale, hatched bars, dashed lines and "SUPUESTO" in titles, hovers and table headers.
  - Model values get a violet scale, dotted bars and lines, and "MODELO". Gross gamma is never mirrored (calls +, puts −), because that would mimic the assumed sign.
  - The map's OI and gross-gamma heatmaps default to a **log** color scale, with percentile and linear options. On a linear scale 384 of 471 cells fell in the lightest step, because 8000 (~2.3M) dwarfs the other zones (50k–600k).
  - Measured values get single-hue scales and solid marks.
  - Light and dark palettes are validated separately with the dataviz validator.
- `app/panel_odte.py` is the 0DTE panel (`streamlit run app/panel_odte.py`): tabs for the day (SPX per minute, touches, pre-open load), per-minute flow, M4, the touch sample, M1/M2 and a cache inventory. It only draws. All data comes from `src/odte/vista.py`, which is **cache-only** (never downloads or quotes; `tests/test_vista.py` makes the download paths raise). Column classes come from `carga.clase`. A day missing something raises `vista.SinDatos` with the reason and the panel shows it instead of breaking; `vista.inventario()` lists every business day (2026-10-20 shows as a day with nothing). Flow exists only for days with catalog + 0DTE tcbbo in cache (9 days, 3 of them partial windows) and covers only the downloaded strikes. Don't pay tcbbo to widen it.
- `app/panel_medidas.py` is the panel for the sign-free measures (`streamlit run app/panel_medidas.py`), kept **separate** from the 0DTE panel by the user's decision. Four headline numbers and four tabs: implied range (straddle vs next-day move, MEDIDO), gamma by price (photo vs recalculated gross gamma by zone at a chosen hypothetical spot, MODELO, with the verified error band for that move size; the assumed net per spot is a separate SUPUESTO chart). The grid is ±1050 pts of the photo's close in 25-pt steps (zones ±1300), so every photo reaches 6800. A move only gets a band if at least `MIN_PARES_BANDA`=3 verified pairs in the **same direction** are that large or larger (`limite_verificado`; with 38 pairs: −1.92% down, +1.31% up). Otherwise `banda_error` returns `SIN_VERIFICAR` (n=0, nan), and the panel marks the bar chart title, shows a warning and shades that strip of the net chart as "MODELO sin verificar" instead of borrowing the "1% o más" band (one −4.4% pair alone does not count). The net per spot sums **all** zones (`gex_bruto_total`/`gex_sup_total`, computed in `rejilla` before the zone cut; summing the saved zones would drop puts at the low edge and calls at the high one), verification, and intraday. It only draws: everything comes from `src/vista_medidas.py`, which reads files already computed (`data/validacion/rango_implicito.csv`, `gamma_verificacion.csv`, `gamma_local.csv` and `data/procesado/perfil_gamma_FECHA.parquet`, written by `scripts/perfil_gamma.py --todas`). It never recalculates, because `perfil_gamma.insumos` needs `config`; a test imports the view in a process without the API key and fails if `config`, `src.datos` or `src.gex` get loaded. A missing file raises `vista_medidas.SinDatos` naming the command that generates it. Column classes come from `vista_medidas.clase`. When MEDIDO and MODELO share a chart they use orange vs violet (`MEDIDO_MIXTO`/`MODELO_MIXTO`): blue vs violet fails the validator's normal-vision floor.
- `app/estilo.py` holds the palette and the per-class marks (`patron_clase`, `linea_clase`, `ROTULO`) shared by the panels. Patterns use `fillmode="overlay"`: with the default, a single-colour patterned bar renders transparent.
- Subagent `.claude/agents/revisor-supuesto-medido.md` is read-only (Read/Grep/Glob). Run it after changing either panel or any script that shows GEX. It checks how a number is **shown**.
- Subagent `.claude/agents/revisor-validacion.md` is read-only too and checks how a number was **obtained**. Run it after adding or changing a `validar_*` / `analizar_*` / `verificar_*` script or any module that computes hit rates, correlations or errors. Six fixed rules: no look-ahead (including scales and thresholds computed with the day being predicted), the naive predictor on the same rows, honest sample (episodes or days, 10-day cells), separate accumulators, closed questions stay closed (M1, M2, M4, Phase B), and cache-only where a script says $0. It also has a standing extra task: propose alternative explanations for each reported relation and the cheapest check from cache.

**0DTE package (`src/odte/`)**: one module per question (see `src/odte/__init__.py`): `catalogo` (the `definition` schema, 0DTE filter), `precio` (SPX per minute = ES 1-min minus the close basis, since OPRA has no index), `trades` (`tcbbo` with a **per-symbol** cache. `asegurar_tcbbo` downloads only the symbols that no cached file of that day covers, where the file's window must contain the requested one. `leer_tcbbo` reads cache only, each symbol from one file, and raises on anything missing. New files carry a `.json` with the requested symbols, so a symbol with no trades still counts as covered. Never read a tcbbo parquet by its exact path; use `leer_tcbbo`), `clasificacion` (midpoint rule vs a strict at-bid/at-ask rule, with a `complejo` flag for prints outside the spread; `estricto` is a required keyword, no default), `flujo` (per-minute public flow; the dealer is the opposite sign), `dealer` (the dealer sign table), `veredicto` (measured dealer sign per strike: a sign only if |neto| >= `MIN_ABS` AND |neto| > the indeterminate volume, worst case; otherwise "sin evidencia" / "indet. domina"; always reported next to `pct_indet`), `cruce` (`corte_strike`: first cross / closest approach, the time cut for "flow before the price arrived"), `calendario` (`hora_cierre`: 16:00 or 13:00 on early-close days; the per-year table raises for an unlisted year; used for the 0DTE expiry and the ES session), `descargas` (`asegurar_odte`), `toques` (M2: `Definicion` of a level touch and its outcome `aguantó`/`cruzó`/`ventana corta`, plus `flujo_previo`, the measured flow before the touch). The M2 sample is `scripts/odte/validar_0dte.py` (tcbbo only for touched strikes; accumulator `data/validacion/odte_toques.csv`, one `definicion` label per parameter set, never mixed with the GEX CSVs) and `analizar_odte.py` ($0; episodes = days). **M2 is closed, structurally "sin evidencia":** before the touch |neto|/indet has median 0.035, ~44% of the indeterminate prints exactly at the mid, and the sign flips in 7 of 16 touches when the interior is signed by proximity. So with OPRA tcbbo and quote rules the aggressor (and the dealer sign) is not identifiable intraday either, as in Phase B. Don't pay tcbbo to widen that sample, and don't relax `veredicto`'s worst case (M1 closure). The next question, M4, is sign-free: does a level with more load (OI) hold more? It is implemented in `carga.py`:
- **Load sources:** OI from the photo of d (measured); gross gamma (model) and the assumed wall from the photo of d−1, without what expires on d.
- **Relative load:** a percentile within the roundness class (100/50/25).
- **Scripts:** `scripts/odte/validar_carga.py` (cache-only, $0, accumulator `data/validacion/odte_carga.csv`) and `analizar_carga.py`.
- **Reference column:** `referencia` sets what the relative load is compared against. `radio250` (fixed design) uses the same-class zones within ±250 pts of the d−1 close. `tocadas` (variant, `--referencia tocadas`) uses only the same-class zones touched that day. The two are analysed apart and never mixed.
- **Result (2026-11-09):** both are "sin evidencia". **M4 is CLOSED as "sin evidencia"**, by the user's decision.
  - `radio250`: 71 touches in 30 days. The load scores 45% against 66% for the base rate, and 77% of touches fall in the "high" half.
  - `tocadas`: only 20 touches in 6 days have a comparison. The difference flips to −4.
- **The limit is the sample:** on most days only one zone per class gets touched.
- **Don't reopen it on spend:** don't pay for photos just to widen M4, don't relax the 10-days-per-cell rule, and don't change the reference or the touch definition to chase a result. Any new variant gets its own label alongside the existing ones (ODTE.md, "Cierre de M4"). `clasificacion.ubicar_trades` says where each print sat (ask/bid/medio/interior/fuera); signing the interior by proximity is INFERRED and goes in separate columns. Constants are in `constantes.py`. Status, risks and the improvement log live in `ODTE.md`.

**Timezones:** every timestamp carries `America/New_York` explicitly. Databento `expiration` is midnight UTC, which falls on the *previous* day in NY. This was the project's first bug and has a regression test in `tests/test_catalogo.py`.

**Scripts (`scripts/`, `scripts/odte/`)** are one-off analyses/visualisations. Each does `sys.path.insert(0, <repo root>)` and then imports from `src`. Their module docstring documents the usage (`Uso: python scripts/... <fecha> [q]`). Charts are saved to `data/*.png` (gitignored). Some results are tracked in git as CSVs:
- `data/validacion/gex_dias.csv` is an **accumulator**. Each `validar_gex` run merges its days into it. `analizar_validacion.py` analyses all accumulated windows at $0.
- `data/b2/flujo_series.csv` is the output of `b2_flujo`.
- `validar_gex ... --spxw` (SPX+SPXW, `plazo="horas"`) writes to a **separate** accumulator, `data/validacion/gex_dias_spxw.csv`, analysed with `analizar_validacion.py <ruta>`. Never mix the two CSVs. `comparar_raices_gex.py` compares configs A (SPX/dias), B (SPX/horas) and C (SPX+SPXW/horas) per date. SPXW costs ~$0.46–0.49 per uncached day (SPX ~$0.20).

**Implied range (`src/rango_implicito.py`, `scripts/validar_rango.py`):** the ATM straddle (call + put at the strike nearest the forward) of the first SPXW expiry after `fecha`, at the closing mid. It is a **measured** price: no dealer sign, no Black-Scholes. The script is **cache-only** for Databento ($0; days without the SPXW chain are skipped and listed) and writes its own accumulator, `data/validacion/rango_implicito.csv`. The SPX daily bars come from yfinance uncached, so a day whose next session has not finished (before 16:30 NY) is skipped rather than saved with a partial bar. Run it with no arguments to analyse only. Predictors are compared after `escala_sin_mirar` (leave-one-out median ratio); `comparar` always gives the **median** error next to the mean, and `robustez` repeats the comparison without the two largest days and by halves.
- **Quote time (measured 2026-11-12 from the cached `statistics`):** the "closing" bid/ask is the options' 16:15 close, published at 16:23 and repeated unchanged at 17:30–17:45. The SPX closes at 16:00, so there are 15 minutes of asynchrony (forward −36.6 pts from spot on 10-29; ≥10 pts on 6 of 31 days). Consequences: the strike comes from the options' own forward; calibration measures what the straddle **pays**, `pago_sig_pct` = |next close − K|, not the move from the 16:00 close; and against `rango_hoy` the straddle has a 15-minute head start, stated and not corrected (without those 6 days it is still ahead: 0.308 vs 0.450).
- **Result, 31 days (09-24..11-06): orientative, not evidence.** Against next-day range the straddle has Spearman +0.41 and mean error 0.424 vs +0.26 / 0.544 for `rango_hoy`, but the **median** error is 0.281 vs 0.272 and it wins 16 of 31 days and 8 of 14 volatility episodes (5 of 7 calendar weeks): the advantage is in the big days. Without the two largest days: 0.316 vs 0.432. In the second half of the window (16 days) it wins 5 days and its median error is worse (0.675 vs 0.376). In ranks the straddle contains the naive predictor (partial Spearman +0.33 for the straddle given today's range, +0.05 the other way). Payoff/cost averages 1.19 (median 0.84; 55% of days below 1). The assumed GEX with sign ranks days about as well (−0.48, same caveat) and has no scale. On 11-04 the straddle was 0.56% before the 4.36% day: the market did not see it either. Episodes are runs of the target above/below its full-sample median, so their count can shift as days are added (16 with a past-only median, straddle still 8).

**Recalculated gamma (`src/perfil_gamma.py`, branch `medidas-sin-signo`):** the photo's gamma re-evaluated at another spot and time, with each option's IV held fixed (sticky strike), the measured `q` and the remaining `T`. Everything is **MODELO** (gross, no sign); the null-hypothesis net is a separate SUPUESTO column (`clase(col)` raises on an unclassified column). `insumos(fecha, r)` is **cache-only**: it joins `q` and `T` from the raw chain onto `data/procesado` (which stores neither) and raises unless the recalculation at the photo's own spot reproduces the stored gamma (identity, 1e-9). It excludes the same-day expiry, like `carga.py`. Three scripts, all $0:
- `scripts/verificar_gamma.py`: the reality check. The gamma of d carried to the spot and time of the d+1 close against the real d+1 photo (same series, OI of d), next to the error of using the stale photo. 29 pairs: recalculated median error 3.5% of the real per-zone gamma (worst 15.6%, on 11-04→11-05) vs 14.0% (worst 37.6%) for the stale photo; better in 27 of 29. For moves ≥1%: 6.4% vs 26.4%. The bias is **not** corrected (that would assume how vol moves). That error is the band any recalculated profile must be read with.
- `scripts/perfil_gamma.py FECHA [spots]` (or `--todas`, which skips grids already saved; add `--rehacer` after changing `ALCANCE_REJILLA`/`ALCANCE_ZONAS`): gross gamma by zone × hypothetical spot, ranking ageing, what is left tomorrow, and the assumed net per spot. The zone **ranking** barely ages (Spearman ~0.9, 4 of 5 top zones stay after the −335 move, because OI sits on round numbers); the **levels** do (7400: 8.5 → 14.0 $B).
- `scripts/validar_gamma_local.py`: sign-free intraday test, accumulator `data/validacion/gamma_local.csv` (30-min blocks from 10:00; honest sample = days). 348 blocks, 29 days. **Result: sin evidencia. **Validation rules (`validar_gex` / `analizar_validacion`, not negotiable):**
- Always compare the day-before-close GEX with what happens next, never with the same day.
- Report GEX changes in $B, not %, because a % change flips sign when GEX is negative.
- Days are not independent, so report **episodes** (same-sign runs). The honest sample size is the number of episodes.
- Every result must beat the **naive predictor**, which is today's range (`rango_hoy`).

## Conventions seen in the code

- Prefer a loud failure ("error que grita") over silently wrong numbers ("error que susurra"): raise `ValueError`/`RuntimeError` with a clear message, and return `nan` rather than a fake value.
- Label every number by what it rests on. "Assumed" (from the null hypothesis) and "measured" (from classified flow) are separate columns, and no conclusion merges them. Below the evidence minimums, the answer is "sin evidencia" or "demasiado chico", never a guess.
- Commit messages are short Spanish summaries of what changed plus the numerical finding (e.g. GEX deltas and test counts).
